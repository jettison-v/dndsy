My answer: yes, a small one

Why: the app has outgrown "decide as we go"

askdnd already has a dark theme, colors and a text-size scale, written down in DESIGN.md. Most of the stylesheet doesn't use them yet. Every screen we built picked its own sizes, so screens that should look the same look slightly different, and each new screen adds more one-off values.

Why now: step 11 adds three more lists (Inventory, Features, Campaign). With a system they're assembled from parts that already exist and look right the first time. Without one, each adds its own sizes and the drift you've been catching by eye (the search box, misaligned headers, text sizes) keeps coming back.

What "great" means for a one-table app

Not a framework or a component library. Four things, sized to askdnd:

1. Tokens

Named values for every size, color, space, corner and screen width. Pages only use the names, so one change updates the whole app.

2. Components

About 15 parts with one name each: button, tag, chip, list row, section, heading, side panel, modal, toolbar, search box, pips, roll button, toast, empty state, help line.

3. A living page

One page in askdnd that shows every component with real markup, so you can review the whole look in one place and new screens start from it.

4. A guardrail

An automatic check (it runs with the tests on every push) that fails if a stylesheet uses a size or color outside the tokens. It keeps the app from drifting again.
