Your question: a table framework?

You asked whether an open-source table library would help with live updates and the layout trouble we keep having. Here are the four well-known ones, measured against how askdnd is built: the server writes each page's HTML, and pieces update in place without a reload.

OptionWhat it isFits askdnd's pagesWhat it would cost us
TabulatorA complete table in plain JavaScript (MIT licence): sorting, filtering, columns that fold away on a phoneThe best fit of the four: needs no frameworkIt draws rows in the browser from data, so every table would also need its data sent separately, and tests that read askdnd's HTML wouldn't see its rows
AG Grid (Community)A spreadsheet-grade grid, free edition (MIT)Works without a framework, but largeHeavy for lists of 5–50 rows, and the same split as Tabulator
TanStack TableThe logic of a table with no look of its own; you draw every cell yourselfMade for React, Vue and the like; askdnd uses noneWe'd still write all the markup, so it fixes none of the layout trouble
askdnd's own table pieceOne table in the design system, used by every Backstage list, with its widths, wrapping and phone layout settled onceIt's how pages are built todayThe work of making the piece and moving lists onto it; nothing new to learn or load

My take: the trouble we've had comes from tables being built one at a time: a column that wraps here, a width that differs there. A library would add a second way to draw tables beside askdnd's own (the one-way-for-each-thing rule) and split every list into a page and its data. One table piece in the design system fixes the cause. If, once it's in, a list needs sorting or filtering beyond it, Tabulator is the one I'd try first.
