One more pass: six changes

1A review is Workshop's, not askdnd's.

Workshop builds more than askdnd, so each review is written once as a template (what it checks, how, what it hands back) and each product fills in its own: for askdnd, Battle, the 2024 books, D&D Beyond, the table's characters. A new product starts with the same ten.

2What a review finds goes through the work flow, not beside it.

Each finding becomes an issue under its Product Area's Feature, sorted like any note, and its fix goes in that Product Area's batch with its lane and check. The review's own page keeps only the real choices; nothing is fixed outside the usual path.

3It never starts on game night.

While Deploys is Paused a scheduled or requested review waits and says so; it starts once you choose another. And one review at a time: a second waits its turn.

4It asks rather than guesses.

A review that needs something from you mid-run (which character shows it, which of two readings is right) puts the question in For you and its row says Waiting on you; it carries on with the rest meanwhile.

5It has a time limit, and skips when there's nothing to look at.

Each run stops at its limit (an hour for most) and reports what it covered; Go over the week with no merged changes since the last run is skipped and says so.

6Its results line up over time.

Every run records the same few numbers (found, fixed, picks, still open), so Scheduled shows whether a review keeps finding things; one that finds nothing three runs in a row comes up in the Look back at how we work to slow down or retire.

How a review starts (as in version 4)

On its scheduleA scheduled task in the Claude app on your MacBook starts it at its time. The Scheduled tab shows each one's next date.
When the MacBook is asleep or offWhen it wakes, one catch-up for the latest missed time (within 7 days); older misses are skipped.
On demandWithin minutes if a Claude session is listening, else an hourly task picks it up. Never while Deploys is Paused.
