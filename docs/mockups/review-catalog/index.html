The reviews we should run

Built the other way round, as you asked: six buckets of the work askdnd needs looked after, each with the question it answers, what's already checked automatically, and the reviews that should cover the rest. What we've run so far helped build the list; it's cited where a review grew from one, and five reviews are new, things past reviews kept running into.

Six buckets

Experience

Is it easy and pleasant to use at the table?

Already checked automaticallyLayout tests at every width, iPhone Safari nightly, the Monday phone sweep, the visual compare before a merge.

  • Game-night walkthroughMonthly

    Battle, Sheet, Party and rolls played as a player and the DM would on a game night, laptop first, then a phone.

    Built from: UI and UX review, Nov 16 ↗, the usability round, the Live UI audit
  • Design review: an areaOn demand · After a big change to an area, or when one feels off.

    One area's every page against the design system and its purpose; rounds of picks until it's one piece.

    Built from: Backstage, Nov 24 ↗
  • Accessibility checkNewEach phase

    Keyboard only, contrast, a screen reader, larger text: can everyone at the table use it?

    Not run yet: something past reviews kept running into
  • Help and guides checkNewMonthly

    Help, the FAQ, the DM guide and the tour against what the app does today.

    Not run yet: something past reviews kept running into

Correctness

Is what askdnd says right?

Already checked automaticallyThe nightly live test on the real D&D Beyond, the daily D&D Beyond drift check, the rules and parser tests.

  • Rules accuracy auditMonthly

    Every button and number on Battle against the 2024 books' own words.

    Built from: Roll audit, Nov 10 ↗, Roll data review
  • D&D Beyond fidelity checkMonthly

    askdnd's numbers for every character against D&D Beyond's own sheet, side by side.

    Built from: Bridge review, Nov 3 ↗, Wild Shape review
  • Feature deep-dive: a featureOn demand · When a feature misbehaves at the table.

    One feature taken all the way down against the real thing.

    Built from: Wild Shape review, Nov 3 ↗

The code

Is it well built, and still easy to change?

Already checked automaticallyTests on every push, the code review on every pull request, the fire drill, Dependabot.

  • Week in reviewWeekly

    The week's changes checked as one by fresh reviewers (design system, code) and a sweep of every page.

    Built from: End-of-day audit, Nov 25 ↗
  • Architecture reviewEach phase

    Knowing every requirement now, would we build it differently? What to keep, change and plan.

    Built from: Backend look-back, Nov 25 ↗, architecture review Nov 2
  • Test health checkNewMonthly

    Do the tests still catch what they should: planted bugs (mutation testing), tests that pass only on a second try, slow ones, untested corners.

    Not run yet: something past reviews kept running into

Trust

Is what people give askdnd safe?

Already checked automaticallyThe refusal and reading tests on every route, the public-repo check, the monthly restore drill.

  • Security and privacy auditEach phase

    Read as an attacker and an auditor would: who sees what, what a request can change, what leaves askdnd.

    Built from: Outside review, Nov 10 ↗
  • Data and retention checkNewEach phase

    What's kept, where and how long: transcripts let go, backups restorable, nothing private in the repo, keys still narrow.

    Not run yet: something past reviews kept running into

Running it

Is it up, quick and affordable?

Already checked automaticallySentry errors filed daily, the slowest pages weekly, backups nightly, the after-deploy check, the spending limit.

  • Operations reviewNewMonthly

    Errors, slow pages, failed jobs and the month's costs (Claude, OpenAI, Railway and its worker) in one look, with what to change.

    Not run yet: something past reviews kept running into

How we work

Is the way we build askdnd working?

Already checked automaticallyThe daily feedback check, the gaps check at the end of every turn.

  • Workshop retroMonthly

    Where time went, what fell through, what waited on whom, and what to change in Workshop.

    Built from: Found, Fixed, Tried audit, Nov 17 ↗, the jobs audit
  • Roadmap checkNewMonthly

    Items gone stale, scopes waiting, whether the order still matches what matters: for you to decide.

    Not run yet: something past reviews kept running into

What every review hands back

1 · In For you
One page: what it found, what's already fixed, and only the real choices as picks with mine marked. Comment, Send now, then pick.
2 · One pull request
What was plainly wrong, fixed together and merged as its lane says; its check reaches your For you once it's live.
3 · Its row on Scheduled
When it ran and what it found, fixed and asked, kept for every run; the page stays in Documents.
