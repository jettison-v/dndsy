# End-to-end live test plan

Run this now and then to prove askdnd still works with the real D&D Beyond (Brett, 2026-10-30). The picture of it all, for reading rather than running: [How askdnd Is Tested](https://claude.ai/artifact/Mwscumi8DvfFvTkL5CzPJG) (`docs/artifacts/testing.html`). The everyday tests use a stand-in for D&D Beyond, so they can't notice D&D Beyond changing, or timing that only shows on the real site. Seats and rules are in [testing-setup.md](testing-setup.md).

## When to run it

- After each extension update reaches the store
- After a change to the bridge, rolls, the Game Log, the fight or Hit Points
- The day before a session
- Whenever D&D Beyond looks different: it can change without notice

Say "run the live tests" and Claude does part 1, then gives you what's left in part 2.

## Before it starts

- [ ] Nobody is playing, and nobody needs Cathartic or Vi: the runs open, close and change those sheets, and put them back
- [ ] Beta has the change to test: the runs test beta, never unmerged work
- [ ] After an extension update: reopen the seats (`real_table_seats.sh close`, then `open`). They update themselves from the store like any Chrome, so don't `copy` for this: a copy from a profile that hasn't updated yet puts the old version back
- [ ] Open the seats: `real_table_seats.sh open`

Part 1 starts with the setup (each player's seat plays its test sheet on beta, and every seat has the same extension: a seat that isn't set up is one setup miss, and the runs on it are left out rather than each missing for the same reason), then checks that the test sheets are clean (full Hit Points, nothing marked, spent or in force), and ends by checking each is back as it found it. A miss at the start means an earlier run didn't put something back: it's reported, and hit points, death saves, conditions, slots and limited uses are put right on D&D Beyond so the rest can run.

**After every run** (Nov 5) its sheets are tidied the same way: a run that left something behind misses there ("put back …"), and the next run starts clean whatever this one did (on Nov 5 one run's leftovers made four more miss). **A run that misses is tried once more** on the tidied sheets: missed twice is a miss (an error in Sentry, which alerts Brett); passed the second time, its first misses are reported as **passed only on a second try** (a warning in Sentry, one issue whose count of events says how often). `--once` skips the second try.

**The history:** every part 1 adds a line to `~/askdnd-tests/logs/results.jsonl` on the Mini, each check with how long it took. `uv run python scripts/live_results.py` (from your Mac) lists, worst first, every check that didn't pass every time over the last 14 nights, and the checks getting slower.

Run it three times after a bridge change: the timing bugs so far only showed in some runs.

**Through the DM** (`real_table.py --via-dm`, Brett 2026-11-04): every run above that changes a sheet, again with every player's sheet closed and only the DM's seat on the campaign page, so the DM's browser makes each change (Manage › askdnd › D&D Beyond bridge's matrix of what each connection can change). Each run first checks the pill says Through the DM and stops if it doesn't: a sheet open in any other browser (yours, on another computer) makes the changes instead, so close D&D Beyond sheets elsewhere while it runs. `closed-sheet`, `game-log`, `close-after-roll`, `dm-backup` and `unreachable` are about the player's own sheet (or close every way in) and stay out.

## Every night: the canary

A canary is a small check that runs on its own and warns you before anyone else notices. At 4:00, Mini time, launchd on the Mac Mini runs `real_table_nightly.sh`: it opens the seats, runs part 1 (then again through the DM, since Nov 4) against beta and closes them. Any miss, or seats that won't open, becomes an issue in [Sentry](https://brett-vw.sentry.io/issues/?project=askdnd-v2) titled "Live test part 1: … missed" (environment `live-test`), which alerts Brett like the app's own errors. Each night's output is in `~/askdnd-tests/logs/nightly-<date>.log` on the Mini. The seats are test accounts, so game nights don't matter.

- **The job:** `~/Library/LaunchAgents/ai.askdnd.live-test.plist` (its source is `scripts/ai.askdnd.live-test.plist`). A Mini asleep at 4:00 runs it when it wakes. To switch it on, from the repo on your Mac: `scp scripts/ai.askdnd.live-test.plist mac-mini-server:Library/LaunchAgents/ && ssh mac-mini-server 'launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/ai.askdnd.live-test.plist'` (on since Nov 2, Brett approved; a deliberate miss reached Sentry).
- **The Sentry key:** `SENTRY_DSN` in `~/askdnd-tests/.env` on the Mini, readable only by its owner, put there with `scripts/set-secret.sh SENTRY_DSN --mini`. Never in git.
- **Try the alert:** `real_table_nightly.sh --try-alert closed-sheet` on the Mini adds one deliberate miss to a short run. Resolve the issue it makes in Sentry afterwards.
- **After changing the scripts:** the Mini runs its own copies. Copy them again: `scp scripts/real_table.py scripts/real_table_seats.sh scripts/real_table_nightly.sh mac-mini-server:askdnd-tests/`.
- **Turn it off:** `launchctl bootout gui/$(id -u)/ai.askdnd.live-test` on the Mini.

## After each deploy: the quick check

Since Nov 5, a deploy that breaks the table is known within minutes, not at 4:00. Every 5 minutes launchd on the Mini runs `real_table_after_deploy.sh`: it asks beta which commit it runs (`/health`'s version), and when that has changed it opens the seats, runs closed-sheet, hit-points, condition and cast (about 3 minutes) and closes them. A miss goes to Sentry as "Live test after deploying …", with its own issue. It and the nightly share the seats through `logs/.seats-busy`: the nightly waits for it, and it tries again 5 minutes later if the nightly or another run has them. Its output is in `~/askdnd-tests/logs/after-deploy-<date>.log`.

- **The job:** `~/Library/LaunchAgents/ai.askdnd.after-deploy.plist` (its source is `scripts/ai.askdnd.after-deploy.plist`). To switch it on, from the repo on your Mac: `scp scripts/ai.askdnd.after-deploy.plist mac-mini-server:Library/LaunchAgents/ && ssh mac-mini-server 'launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/ai.askdnd.after-deploy.plist'`. Its first look only remembers beta's version; the next deploy runs it.
- **Turn it off:** `launchctl bootout gui/$(id -u)/ai.askdnd.after-deploy` on the Mini.
- **Running part 1 by hand on the Mini:** check the after-deploy check isn't running first (`ls ~/askdnd-tests/logs/.seats-busy`: no such folder means the seats are free).

## Every morning: D&D Beyond drift

The other tests read D&D Beyond through copies in `tests/fixtures/ddb`. At 12:30 UTC GitHub runs `scripts/ddb_drift.py` (the workflow "D&D Beyond drift"): it reads today's three test sheets as askdnd does, says if a field the copies have is gone or has changed kind, and runs askdnd's parser on each to check what every character has comes out (a name, level, Hit Points, AC, abilities, saves, skills, a class, actions, items, spells). A miss fails the run and GitHub emails Brett: refresh the copies (`scripts/ddb_fixture.py`) and fix the parser.

## Part 2: by hand, about 15 minutes

These need a person, or D&D Beyond's VTT, which is a game canvas a script can't read reliably.

1. **A fight.** DM: in the [VTT](https://www.dndbeyond.com/campaigns/8224496), start an encounter with Cathartic, Vi and a monster. The fight band shows the order, and Table rolls opens once on each player's page.
2. **Turns.** Press Next a few times. The band follows, and a hidden monster is hidden from players.
3. **A condition that ends.** Give Cathartic a condition lasting until the end of their next turn. A corner card reminds the player and the DM when it's due. Nothing ends by itself.
4. **The DM's roll.** Roll a monster's damage in the VTT. It appears in Table rolls with **Apply to**, and applying it changes the sheet.
5. **Rolls in the Game Log.** With the Game Log open on D&D Beyond, roll in askdnd. It shows there marked ⓐ, once. The automatic run sees the message pass, not how it looks.
6. **Dying.** Bring a seat's character to 0, roll a death save, heal. The Dying tile, marks and Unconscious all follow.
7. **Dice.** Watch a 3D throw land on the right number, then check that nothing replays after you've been in another tab.
8. **A second device.** Open askdnd on a phone: the pill and Table rolls read properly.

## After a run

- Check [Sentry](https://brett-vw.sentry.io/issues/?project=askdnd-v2): a run can pass while something fails quietly.
- Add a line below.
- A failure caused by D&D Beyond's page changing is a fix to `scripts/real_table.py`. A failure in askdnd becomes a bug with a test that fails without its fix.
